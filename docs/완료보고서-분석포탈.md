## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 프로젝트명 | AI 데이터 분석 포털 (MLFoundry) |
| 목적 | 데이터 분석·ML·AI 추론 도구를 **단일 포털·단일 로그인**으로 통합 제공 |

## 4. 서버 동작 상세

### 4-1. 시작 시퀀스 (lifespan)

```
uvicorn 시작
    │
    ├─ [1] SQLAlchemy create_all()
    │       → users, user_feature_permissions, user_service_tokens,
    │         board, board_file, datasets, data_query_history,
    │         system_settings (테이블 자동 생성, 없을 때만)
    │
    ├─ [2] ensure_default_users()
    │       → admin / user 계정 없으면 자동 생성
    │         (비밀번호: PBKDF2-SHA256 × 120,000회 해시)
    │
    └─ [3] ensure_default_settings()
            → system_settings 테이블에 초기값 12개 시드
              (MLFLOW_BASE_URL, JUPYTER_BASE_URL, JUPYTER_ENVS,
               ATHENA_DATABASE, ATHENA_S3_OUTPUT, S3_BUCKET_NAME,
               JUPYTERHUB_ADMIN_TOKEN, AIRFLOW_BASE_URL 등)
```

### 4-2. 인증 흐름

```
[브라우저 - 로그인 페이지]
    │  POST /api/auth/login  (Form: username, password)
    ▼
[AuthService.login()]
    ├─ DB에서 User 조회
    ├─ PBKDF2-SHA256 비밀번호 검증 (hmac.compare_digest 타이밍 공격 방지)
    └─ JWT 생성: {sub: username, role: admin|user, exp: +480분}
         서명: HMAC-SHA256 (SECRET_KEY)

[브라우저] ← access_token (localStorage 저장)

이후 모든 API 요청:
    Authorization: Bearer {access_token}
    │
    ▼
[deps.get_current_user()]
    ├─ Bearer 토큰 파싱 → decode_access_token()
    ├─ HMAC 서명 검증 + 만료 확인
    └─ DB에서 User 재조회 → UserRead 반환

[기능 권한 체크 - require_feature("athena" 등)]
    ├─ role == "admin" → 전체 허용
    └─ user_feature_permissions 테이블 조회 → 미허용 시 403
```

### 4-3. 데이터베이스 구조 (PostgreSQL RDS)

| 테이블 | 역할 | 주요 컬럼 |
|--------|------|-----------|
| `users` | 포털 사용자 | id, username, password_hash, name, role(admin\|user) |
| `user_feature_permissions` | 기능별 접근 권한 | user_id, feature(s3\|athena\|jupyter\|mlflow\|airflow) |
| `user_service_tokens` | JupyterHub·MLflow SSO 토큰 | user_id, service, token, UNIQUE(user_id, service) |
| `board` | 게시판 | title, content, created_by, created_at |
| `board_file` | 게시판 첨부파일 | board_id, filename, s3_key |
| `datasets` | 데이터셋 메타데이터 | name, description, s3_path, schema |
| `data_query_history` | SQL/Athena 실행 이력 (감사) | user_id, sql_text, row_count, status, executed_at |
| `system_settings` | UI 수정 가능 시스템 설정 | key(PK), value, label, group, updated_at |

## 6. 보안 설계

| 항목 | 구현 |
|------|------|
| 비밀번호 해시 | PBKDF2-SHA256 × 120,000회 + 사용자별 salt (`username:SECRET_KEY`) |
| JWT | HMAC-SHA256 서명, TTL 480분 (8시간) |
| 타이밍 공격 방지 | `hmac.compare_digest()` 상수 시간 비교 |
| 기능 권한 격리 | `user_feature_permissions` — admin은 전체 허용, user는 명시적 부여 필요 |
| SSRF 차단 | 클라우드 메타데이터(169.254.169.254 등) 및 미허용 호스트 차단 |
| 감사 추적 | 쿼리 실행 이력(`data_query_history`), S3 다운로드 로그 |
| 시크릿 관리 | k8s Secret → Pod 환경변수 주입 (소스에 평문 없음) |
| AWS 접근 | IRSA(IAM Roles for Service Accounts) — 자격증명 하드코딩 없음 |
